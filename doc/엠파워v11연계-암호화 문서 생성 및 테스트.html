00

먼저 알아 둘 것

왜 웹 다운로드로는 안 되나

엠파워 웹에서 파일을 내려받으면 서버가 풀어서 준다. 우리가 필요한 것은 풀리기 전, 서버 디스크에 놓인 잠긴 파일이다. 그래서 서버에 SSH 로 들어가 저장소의 파일을 직접 복사한다.

받는 방법받는 것테스트에 쓸 수 있나
웹 화면의 다운로드풀린 원본 (분류테스트_워드문서.docx)아니오
서버 저장소에서 복사 (이 가이드)잠긴 파일 (F_f095df74….SMF)예

필요한 것

  • 웹 계정 — 문서를 올릴 엠파워 로그인 계정.
  • 서버 SSH 계정 — mpower@10.10.19.40. 저장소 파일을 읽고 /MOCOMSYS/MpowerScript/removeenc/ 에 파일을 쓸 수 있어야 한다.
  • PC — Python, 그리고 ssh · scp 명령(윈도우 10/11 기본 포함, 또는 Git Bash).

올릴 문서를 enc_test\orig\ 에 모은다. 규칙은 두 가지다.

  1. 이름 앞에 같은 접두어를 붙인다 — 예: 분류테스트_. 나중에 서버에서 "이 글자로 시작하는 파일"만 골라 내는 데 쓴다.

원본 지문 적어 두기

올리기 전에 원본의 SHA-256 을 적어 둔다. 나중에 복호화한 결과의 지문이 이것과 같으면 "제대로 풀렸다"는 증거가 된다.

# Git Bash — enc_test\orig 폴더에서
sha256sum * > ../orig_sha256.txt
# PowerShell — enc_test\orig 폴더에서 (PowerShell 에는 sha256sum 이 없다)
$l = Get-ChildItem -File | ForEach-Object { (Get-FileHash -LiteralPath $_.FullName -Algorithm SHA256).Hash.ToLower() + " *" + $_.Name }
[IO.File]::WriteAllLines("$PWD\..\orig_sha256.txt", $l)
주의

PowerShell 에서 sha256sum * > ../orig_sha256.txt 를 치면 "용어가 인식되지 않습니다" 오류가 나고, 그 사이에 orig_sha256.txt 가 빈 파일로 덮어써진다(> 가 먼저 파일을 비운다). 그렇게 됐으면 위 둘 중 하나로 다시 만든다. 파일 한 줄의 모양은 <지문> *<파일이름> 이다.

팁

같은 파일을 여러 번 올리면 서버에 버전이 쌓여 목록에 여러 줄로 나온다. 테스트 문서는 한 번씩만 올린다.

server_path테스트용 메모. 서버에 있던 원래 경로를 적어 둔 것이다. MpowerClassify 는 이 칸을 읽지 않는다(아래 "중요 ①")

중요 ①

server_path 는 연동에 필요한 칸이 아니다. MpowerClassify 가 목록에서 읽는 칸은 path · sfile_id · hash · mrk · enc_mode · zip_mode · name · size 뿐이고, 그 밖의 칸은 무시한다. removeenc.sh 의 -s(원본 경로)에는 언제나 path 가 들어간다.

그러면 왜 이 문서의 목록에는 server_path 가 있나 — 윈도우 PC 에서 시험하려고 fetch_enc.py 가 넣은 것이다. 파일을 PC 로 받아 오면 path 를 PC 경로로 바꿔야 하는데, 그러면 "원래 서버 어디에 있던 파일인지"가 사라진다. 그 값을 잃지 않으려고 옆 칸에 적어 둔 메모다.

어디서 실행하나path 에 넣는 값server_path
엠파워 서버에서 직접 (운영 형태) 서버의 암호화 파일 경로
VOL_PATH / RFILE_PATH / RFILE_NAME		 넣지 않는다
윈도우 PC + 중계 스크립트 (이 문서의 테스트) PC 에 받아 둔 파일 경로
D:/…/sample/enc/F_….SMF		 없어도 된다(참고용 메모)

엠파워가 실제 연동용으로 만드는 목록은 이 모양이면 된다 — path 에 서버 경로가 들어가고 server_path 는 없다.

{"path":"/(VOL_PATH)/(RFILE_PATH)/F_f095df74b5f78be9057020c73ec809d7.SMF",
 "sfile_id":"SF_…", "mrk":"(평문 열쇠)", "enc_mode":3, "zip_mode":0,
 "name":"분류테스트_워드문서.docx", "size":28367}
중요 ②

size 는 바이트 단위의 "원래 파일 크기"다. 엠파워 DB 의 LFILE_SIZE 값 그대로이며, 암호화되기 전 문서의 크기다 (저장된 파일의 크기가 아니다). 예: 워드문서의 28367 은 PC 에 보관한 원본 파일의 크기 28,367 바이트와 같다. 필수가 아니다 — 없으면 크기 검사만 건너뛴다.

무엇에 쓰나. 복호화가 끝난 뒤 "풀린 파일의 크기가 이 값과 같은가"를 본다. 다르면 그 문서는 분류하지 않고 decrypt_failed(detail: size_mismatch)로 남긴다.

이 검사가경우왜
잡는다쓰다 만 파일디스크가 찼거나 도구가 중간에 죽으면 일부만 쓰여 크기가 작다
잡는다저장 시 압축(zip_mode≠0)이 제대로 안 풀린 파일풀린 크기가 원래와 달라진다. ※ 이 서버에는 그런 파일이 없어 실제로 확인하지는 못했다
못 잡는다틀린 열쇠로 풀린 파일 암호화해도 크기가 그대로이고(모드 3), 틀린 열쇠로 풀어도 같은 크기의 쓰레기가 나온다. 4단계·6-7 에서 실제로 확인했다

왜 넣었나. 엠파워 자신이 이 검사를 한다 — 복호화 공통 함수(class.MCrypt.php 의 mpowerDecrypt)는 풀고 나서 크기가 LFILE_SIZE 와 다르면 실패로 처리한다. 그런데 우리가 부르는 removeenc.php 에는 그 검사가 빠져 있다. 그래서 MpowerClassify 가 대신 한다.

정리

틀린 열쇠를 가려내는 것은 size 가 아니라 name 이다 — 확장자를 보고 풀린 파일의 앞머리(시그니처)가 그 형식인지 확인한다. 둘 중 하나만 줄 수 있다면 name 이 더 중요하고, 둘 다 주는 것이 가장 좋다. 두 값 모두 SHARE_FILE_INFO 의 같은 행에 있어 함께 뽑는 데 비용이 들지 않는다.

모드와 실제가 맞다enc=0, zip=0 이면 평문이어야 하고, 아니면 암호화돼 있어야 한다 zip 은 (0,0) 이고 받은 파일이 원본과 지문까지 같다

스크립트는 열쇠 값을 화면에 찍지 않고 길이만 보여 준다.

이번 자료에서 알게 된 것

  • 암호화해도 크기가 변하지 않는다(모드 3). 그래서 틀린 열쇠로 풀린 결과를 크기로는 가려낼 수 없고, 파일 앞머리(시그니처)를 봐야 한다.
  • 모든 파일이 암호화되는 것은 아니다. zip 은 서버가 (0,0) 으로 그대로 저장했다. 이런 파일은 복호화 도구를 부르지 않고 바로 읽어야 한다.
  • 저장 이름에는 단서가 없다(F_….SMF). 목록의 name 이 없으면 무슨 형식인지 이름으로는 알 수 없다.
  • 이 서버에는 저장 시 압축(zip_mode≠0)을 쓴 파일이 없다. 압축 해제 경로는 이 자료로는 시험할 수 없다.

06

복호화 테스트 — 윈도우 PC 에서 진짜로 풀어 보기

여기까지 오면 손에 잠긴 파일 6개와 열쇠가 든 목록이 있다. 이제 MpowerClassify 가 이 파일을 제대로 풀어서 분류하는지 본다. 아래는 2026-10-12 에 실제로 돌린 과정과 화면 그대로다.

6-1. 먼저 — 왜 "중계"가 필요한가

MpowerClassify 는 복호화를 직접 하지 않는다. 엠파워의 removeenc.sh 를 불러서 시킨다. 실제로 푸는 것은 엠파워 서버에만 있는 프로그램이다.

MpowerClassify-rs  →  removeenc.sh (bash)  →  removeenc.php (PHP)  →  mpower_decrypt()  ← 엠파워 전용 확장 "Mpower 64File"

로컬 PC 의 C:\svn\Mpower_v11\…\removeenc 폴더에는 removeenc.sh 와 removeenc.php 가 있지만, 그것만으로는 풀 수 없다. 그 둘은 "풀어 달라고 부탁하는 글"일 뿐이고, 실제로 푸는 확장이 이 PC 에 없기 때문이다. 로컬 경로를 그대로 줘 보면 이렇게 끝난다.

MpowerClassify-rs.exe --filelist sample\enc\filelist.jsonl --rule-only --json-errors ^
    --decrypt-cmd "C:\svn\Mpower_v11\PHP\Mpower_11.0\MpowerScript\removeenc\removeenc.sh"

{"error":{"code":3006,"kind":"decrypt_unavailable","message":"… 복호화 도구를 실행하지 못했습니다: …removeenc.sh
          (%1은(는) 올바른 Win32 응용 프로그램이 아닙니다.)"}}        ← 종료코드 2, 한 건도 처리하지 않음
필요한 것이 PC엠파워 서버
removeenc.sh · removeenc.php있음(svn 소스)있음
.sh 를 실행할 환경 · /MOCOMSYS/.bash_profile · PHP없음있음
복호화 확장 Mpower 64File없음(svn 에도 없다)있음

그래서 "파일을 서버로 보내 거기서 풀고, 풀린 것을 도로 받아 오는" 심부름꾼을 중간에 세운다. 이것이 중계 스크립트다.

원리

--decrypt-cmd 에는 removeenc.sh 와 같은 인자(-s -t -k -e -z)를 받는 실행 파일이면 무엇이든 줄 수 있다. MpowerClassify 는 상대가 진짜 도구인지 중계인지 모른다 — 인자를 주고, 종료코드와 풀린 파일만 본다.

6-2. 중계 스크립트가 하는 일

sample\enc_test\relay_removeenc.cmd 는 한 줄짜리 껍데기이고(윈도우가 실행할 수 있게), 실제 일은 relay_removeenc.py 가 한다. 문서 한 건마다 아래 네 가지를 한다.

순서하는 일쓰는 도구예 (워드문서 한 건)
①PC 의 암호화 파일을 서버 /tmp 로 올린다pscp F_f095df74….SMF → /tmp/cso_relay_1234_ab12cd34.enc
②서버에서 removeenc.sh 를 실행한다plink removeenc.sh -s ….enc -t ….dec -k (열쇠) -e 3 -z 0
③풀린 파일을 PC 의 임시 위치로 받는다pscp /tmp/….dec → …\cso_dec_5678\000005\000005.docx
④서버의 임시 파일 둘을 지운다(성공·실패 무관)plink rm -f ….enc ….dec

끝나면 removeenc.sh 의 종료코드를 그대로 돌려준다. 중계 자체가 실패하면(접속 불가 등) 200 을 돌려준다 — removeenc 의 코드와 겹치지 않는 번호다.

MpowerClassify-rs.exe 는 서버가 어디인지 모른다. 중계 스크립트에 -s -t -k -e -z 만 넘길 뿐이다. 서버 주소는 중계 스크립트가 .env_v11 의 SSH_SERVER 에서 읽는다. 그 파일은 아래 차례로 찾고, 먼저 찾은 것 하나만 쓴다.

6-7. 틀린 열쇠로 돌려 보기 — 가장 중요한 시험

6-10. 중계에서 막혔을 때

증상원인해결
결과의 error.rc 가 200, reason 에 "relay: 서버로 올리지 못했습니다 …" 중계 자체가 실패했다 — 접속이 안 되거나 비밀번호·계정이 틀렸다 6-4 처럼 한 건을 손으로 돌려 화면의 문구를 본다. 실제로 읽히는 .env_v11(6-3 의 찾는 순서 — 보통 sample\enc_test\ 의 것)의 세 값을 확인한다
문구에 host key · hostkey 가 보인다 서버를 다시 설치해 호스트 키가 바뀌었다. 스크립트는 2026-10-12 의 지문만 믿도록 고정돼 있다 서버가 바뀐 것이 맞는지 확인한 뒤 relay_removeenc.py 의 HOSTKEY 를 새 지문으로 바꾼다
"plink 를 실행하지 못했습니다"PuTTY 가 없거나 PATH 에 없다PuTTY 를 설치한다
"접속 정보 파일이 없습니다 — 찾아본 곳: …" / "SSH_USER_PWD 가 없습니다"세 자리 어디에도 .env_v11 이 없거나, 찾은 파일의 값이 비었다 문구에 찾아본 경로가 모두 나온다. sample\enc_test\.env_v11 을 만들어 세 값을 채운다
엉뚱한 서버로 붙거나, 값을 고쳤는데 그대로다고친 파일이 아니라 앞 차례의 다른 파일이 읽히고 있다(같은 폴더 → RELAY_ENV → 최상위) sample\enc_test\.env_v11 이 있는지 먼저 본다. 있으면 그것이 쓰인다
error.rc 가 56 → 실행이 즉시 멈춤(decrypt_unavailable)서버의 PHP 가 확장 Mpower 64File 을 읽지 못했다엠파워 서버 설치를 점검한다(엠파워 담당자)
error.rc 가 14열쇠가 v2: 로 감싼 값이다목록을 다시 뽑는다(3단계의 서버 스크립트가 벗겨 준다)
error.detail 이 timeout한 건이 60초를 넘겼다(망이 느리거나 파일이 크다)--decrypt-timeout 180 처럼 늘린다
주의

중계는 테스트 서버 · 더미 문서 전용이다. 열쇠가 SSH 명령줄에 실리고, 풀린 문서가 망을 한 번 더 건넌다. 운영에서는 엠파워 서버에서 MpowerClassify 를 직접 돌린다(5단계 ②) — 그때는 --decrypt-cmd 를 줄 필요도 없다.
