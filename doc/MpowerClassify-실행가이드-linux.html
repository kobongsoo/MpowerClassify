★ 엠파워 v11 암호화 문서 분류 2026-10-12 신규

엠파워 v11 저장소의 문서는 잠긴 채(암호화된 채) 디스크에 놓여 있습니다. 잠긴 파일을 그대로 읽으면 뜻 없는 글자뿐이라 분류할 수 없습니다. 그래서 열쇠를 함께 주면 분류 직전에 엠파워의 복호화 도구(removeenc.sh)로 한 건씩 풀어서 분류하고, 끝나면 풀린 파일을 바로 지웁니다.

금고에 비유하면 — 문서는 금고 안에 있고, mrk 가 그 금고의 열쇠입니다. 이 프로그램은 금고를 직접 열지 못합니다. 열쇠를 받아 엠파워의 도구에게 "이걸 열어 달라"고 부탁하고, 꺼낸 문서를 읽고 등급을 매긴 뒤 꺼낸 사본을 없앱니다. 금고 안의 원본은 건드리지 않습니다.

먼저 — 세 가지 경우만 기억하면 됩니다

경우무엇을 주나동작
① 여러 건 (권장)--filelist 목록의 각 줄에 mrk · enc_mode · zip_mode 를 적는다 열쇠가 적힌 줄만 풀어서 분류. 새 옵션이 필요 없습니다
② 한 건--file 에 --decrypt --mrk --enc-mode --zip-mode 를 붙인다그 파일을 풀어서 분류
③ 이미 풀린 파일아무것도 붙이지 않는다지금까지처럼 그대로 읽어 분류(복호화 없음)

한 건이 처리되는 순서 — 여러 건이어도 한 번에 한 건만 풀려 있습니다.

  1. 푼다 — 임시 폴더에 풀린 사본을 만든다(복호화 도구 호출)
  2. 확인한다 — 제대로 풀렸는지 본다(크기 · 파일 앞머리가 그 형식이 맞는지)
  3. 분류한다 — 본문을 읽고 등급·업무분류를 매긴다
  4. 지운다 — 풀린 사본을 지우고 다음 문서로 간다(실패해도, 중간에 멈춰도 지웁니다)

① 여러 건 — 목록(--filelist)에 열쇠를 적는다

목록은 한 줄에 문서 하나입니다. 아래 예는 세 가지 줄이 섞여 있습니다.

# ① 잠긴 문서 — 열쇠 세 칸이 있으므로 풀어서 분류한다
{"path":"/저장소/…/F_f095df74.SMF","sfile_id":"SF_aaa","mrk":"(평문 MRK)","enc_mode":3,"zip_mode":0,"name":"워드문서.docx","size":28367}
# ② 잠기지 않은 문서(둘 다 0) — 도구를 부르지 않고 그대로 읽는다
{"path":"/저장소/…/F_cb3fd2de.SMF","sfile_id":"SF_bbb","mrk":"(평문 MRK)","enc_mode":0,"zip_mode":0,"name":"압축묶음.zip","size":780690}
# ③ 열쇠 칸이 없는 줄 — 풀지 않고 그대로 읽는다
{"path":"/data/plain/사내규정.pdf","sfile_id":"SF_ccc"}
./MpowerClassify-rs --filelist /tmp/job/filelist.jsonl --simple --format jsonl \
    --out /tmp/job/result.jsonl --json-errors --nosummary

줄의 모양에 따라 이렇게 움직입니다. 줄마다 따로 판단하므로 한 목록에 섞여 있어도 됩니다.

줄에 있는 칸동작
path · sfile_id 만풀지 않고 그대로 읽어 분류
+ mrk · enc_mode · zip_mode (둘 중 하나라도 0 이 아님)풀어서 분류
+ enc_mode:0 · zip_mode:0도구를 부르지 않고 그대로 읽어 분류 (엠파워도 이 경우 잠그지 않고 저장합니다 · mrk 는 없어도 됩니다)
셋 중 일부만 있음 (예: mrk 만)그 문서만 실패로 남김 — info_incomplete
mrk 가 v2: 로 시작그 문서만 실패로 남김 — key_wrapped (아래 "v2: 란")

칸의 뜻

칸뜻엠파워 DB 의 어느 값인가
path이 프로그램이 도는 컴퓨터에서 본 잠긴 파일의 전체 경로VOL_PATH/RFILE_PATH/RFILE_NAME
sfile_id문서 번호. 결과의 doc_id 로 나옵니다SFILE_ID
mrk문서를 푸는 평문 열쇠MRK 를 decryptMRKWithKEK() 로 벗긴 값
enc_mode · zip_mode잠근 방식 · 저장할 때 압축한 방식. 0 도 올바른 값입니다ENC_MODE · ZIP_MODE
name (권장)원래 파일 이름. 저장된 이름(F_….SMF)에는 확장자가 없어서, 이것이 있어야 어떤 형식인지 알고 틀린 열쇠를 가려냅니다LFILE_NAME
size (선택)원래 파일 크기(바이트). 풀린 결과의 크기와 견줍니다LFILE_SIZE

이 밖의 칸(예: server_path)은 읽지 않고 무시합니다.

② 한 건 — --file 에 --decrypt 를 붙인다

# 가) 저장소의 잠긴 파일을 풀어서 분류
./MpowerClassify-rs --file "/저장소/…/F_f095df74.SMF" --decrypt \
    --mrk "(평문 MRK)" --enc-mode 3 --zip-mode 0 --name "워드문서.docx" \
    --simple --json-errors

# 나) 열쇠를 명령줄에 남기고 싶지 않을 때 — 환경변수로 준다
export CSOCLASSIFY_MRK="(평문 MRK)"
./MpowerClassify-rs --file "/저장소/…/F_f095df74.SMF" --decrypt --enc-mode 3 --zip-mode 0 \
    --name "워드문서.docx" --simple --json-errors

# 다) 풀어서 본문만 뽑아 보기(제대로 풀리는지 눈으로 확인)
./MpowerClassify-rs --text-only --file "/저장소/…/F_f095df74.SMF" --decrypt \
    --mrk "(평문 MRK)" --enc-mode 3 --zip-mode 0 --name "워드문서.docx"

--decrypt 는 --file 한 건에만 씁니다. 폴더(--dir)나 목록 실행에는 붙이지 않습니다 — 파일마다 열쇠가 다르기 때문에, 여러 건은 목록의 각 줄에 적는 것이 맞습니다.

③ 풀지 않는 경우

# 이미 풀어 둔 파일 — 아무것도 붙이지 않는다(추가 복호화 없음)
./MpowerClassify-rs --file "/tmp/dec/워드문서.docx" --simple --json-errors

# 목록에 열쇠가 있어도 이번에는 풀지 않고 돌린다
./MpowerClassify-rs --filelist /tmp/job/filelist.jsonl --no-decrypt --simple --format jsonl --out /tmp/job/result.jsonl

인자 한눈에

인자값뜻예
--decrypt—이 파일(--file)을 풀어서 분류한다--file F_….SMF --decrypt
--mrk평문 열쇠문서를 푸는 열쇠. 환경변수 CSOCLASSIFY_MRK 로도 줄 수 있습니다(명령줄에 안 남음). v2: 로 시작하는 값은 받지 않습니다--mrk "…"
--enc-mode숫자잠근 방식(DB 의 ENC_MODE)--enc-mode 3
--zip-mode숫자저장 시 압축 방식(DB 의 ZIP_MODE)--zip-mode 0
--name파일 이름원래 파일 이름. 형식 판별과 틀린 열쇠 가려내기에 씁니다 (권장)--name "워드문서.docx"
--no-decrypt—목록에 열쇠가 있어도 풀지 않는다--filelist … --no-decrypt
--decrypt-cmd경로복호화 도구 위치. 환경변수 CSOCLASSIFY_DECRYPT_CMD. 기본 /MOCOMSYS/MpowerScript/removeenc/removeenc.sh--decrypt-cmd /opt/x/removeenc.sh
--decrypt-tmp폴더풀린 사본을 잠깐 둘 곳. 환경변수 CSOCLASSIFY_DECRYPT_TMP. 기본은 시스템 임시 폴더--decrypt-tmp /dev/shm/cso
--decrypt-timeout초 기본 60복호화 한 건의 시간 제한. 넘으면 그 문서만 실패(timeout)로 남깁니다--decrypt-timeout 120

--mrk · --enc-mode · --zip-mode · --name 은 --decrypt 와 함께만 씁니다. 아래 셋(--decrypt-cmd · --decrypt-tmp · --decrypt-timeout)은 목록 실행에도 그대로 듣습니다.

풀린 파일은 어디에 생기고, 언제 지워지나

풀린 파일의 경로를 부르는 쪽이 알 필요는 없습니다. 어디에 풀지는 이 프로그램이 스스로 정해서 복호화 도구에 알려 주고(removeenc.sh 의 -t 인자), 같은 자리에서 읽어 분류합니다. 그래서 목록이나 --file 에는 잠긴 파일의 경로만 주면 됩니다.

단계경로설명
바탕 폴더--decrypt-tmp → 환경변수 CSOCLASSIFY_DECRYPT_TMP → 시스템 임시 폴더 (환경변수 TMPDIR 이 있으면 그 값, 없으면 /tmp)앞의 것이 있으면 그것을 씁니다
실행마다 한 폴더<바탕>/cso_dec_<프로세스번호>/이번 실행만의 작업장. 리눅스에서는 권한 700(다른 계정이 못 봄)
문서마다 한 폴더·한 파일…/000001/000001.docx이름은 순번, 확장자만 name 에서 가져옵니다

아래는 2026-10-13 에 윈도우 PC 에서 암호화 문서 9건을 돌리며 임시 폴더를 지켜본 실제 결과를 리눅스 경로로 옮겨 적은 것입니다 (같은 코드가 돕니다. 리눅스 서버에서 직접 지켜본 것은 아닙니다). 한 번에 한 건만 있다가 사라집니다.

/tmp/cso_dec_12345/
   000001/000001.pdf     1,226,050 B   ← 1번째 문서를 분류하는 동안만 있다
   000002/000002.hwpx       54,987 B   ← 2번째 문서. 이때 000001 폴더는 이미 지워졌다
   000003/000003.doc       146,944 B
   …
   000008/000008.txt           215 B
   000010/000010.docx       28,367 B   ← 9번이 없는 것은 그 문서가 잠기지 않은(0,0) zip 이라 도구를 부르지 않아서
(실행이 끝나면 cso_dec_… 폴더 자체가 없어진다)

--file 한 건을 --decrypt 로 돌려도 같습니다 — cso_dec_<번호>/000001/000001.docx 가 생겼다가, 분류가 끝나면 폴더째 사라집니다(지켜본 실행에서는 생성부터 삭제까지 약 1초).

언제무엇을 지우나
문서 한 건의 분류가 끝나면그 문서의 폴더(000001)를 바로 지웁니다 — 실패한 문서도 지웁니다
실행이 끝나면cso_dec_<번호> 폴더를 통째로 지웁니다. 오류로 멈추거나 Ctrl+C 로 끊어도 지웁니다
강제 종료돼 지울 기회가 없었으면다음 실행이 시작할 때 주인 없는 cso_dec_* 폴더를 치웁니다
왜 문서마다 폴더(000001 · 000002 …)를 두나 — 문서 하나에서 나온 것을 한 번에, 빠짐없이 지우기 위해서입니다. 풀린 문서가 압축 파일이면 그 안의 문서들을 다시 펼치므로 한 문서에서 파일이 여러 개 나옵니다. 복호화 도구가 대상 경로 옆에 중간 파일을 남길 수도 있습니다. 폴더로 묶어 두면 "그 폴더를 지운다" 한 번으로 끝나고, 하나라도 빠뜨려 풀린 원문이 남는 일이 없습니다.
왜 이름이 순번인가 — 문서 이름 자체가 민감할 수 있고(예: 구조조정_대상자.xlsx), 공백·괄호·특수문자가 든 이름은 도구에 넘기는 경로를 깨뜨릴 수 있어서입니다. 이 임시 경로는 결과에도 로그에도 나오지 않습니다 — 결과의 file 은 준 경로 그대로입니다.

--decrypt-cmd · --decrypt-tmp — 언제 주나

① --decrypt-cmd (복호화 도구 위치) — 도구는 인자 → 환경변수 CSOCLASSIFY_DECRYPT_CMD → 기본 위치 순으로 찾습니다.

실행하는 곳--decrypt-cmd이유
엠파워 서버 (운영)필요 없다 기본 위치 /MOCOMSYS/MpowerScript/removeenc/removeenc.sh 에 도구가 있습니다
엠파워가 다른 경로에 설치된 서버준다 기본 위치에 도구가 없습니다. 환경변수 CSOCLASSIFY_DECRYPT_CMD 로 한 번 정해 두면 편합니다
윈도우 PC (시험)꼭 준다 윈도우에는 도구가 없어 중계 스크립트를 줍니다 → 테스트 문서
엠파워가 없는 리눅스 서버 (시험 — 예: 개발 서버 DEV-SVR, 실제 주소는 .env_vllm 의 SSH_SERVER)꼭 준다 도구가 없어 둘 중 하나를 줍니다(아래 예).
· Docker 판 sample/enc_test/removeenc_docker.sh — 엠파워의 PHP·mpower.so 를 컨테이너에서 그대로 돌려 이 서버 안에서 풉니다(권장)
· 중계 sample/enc_test/relay_removeenc.sh — 엠파워 서버로 파일을 보내 풀고 다시 받아 옵니다

도구가 없거나 실행 권한이 없으면 문서를 한 건도 읽지 않고 1015 decrypt_cmd_missing(종료코드 3)으로 멈추므로, 경로가 틀렸는지는 바로 알 수 있습니다.

엠파워가 없는 리눅스 서버에서 시험할 때 ① — Docker 판 2026-10-16 추가 · 권장 — MpowerClassify-rs 폴더에서 실행합니다.

# 처음 한 번 — 실행 권한, 그리고 Rocky Linux 8 이미지(엠파워 서버와 같은 glibc 2.28)
chmod +x sample/enc_test/removeenc_docker.sh
docker pull rockylinux:8

# 실행 — 엠파워의 진짜 removeenc.php · mpower.so 로 이 서버 안에서 푼다
./MpowerClassify-rs --filelist sample/enc/filelist.jsonl --json-errors --decrypt-cmd sample/enc_test/removeenc_docker.sh --decrypt-timeout 120 --daemon --simple
  • 필요한 것 — 같은 폴더의 sample/enc_test/mpower_rt/(엠파워 서버에서 가져온 php · mpower.so · removeenc.php · lib/, 약 150MB), 그리고 실행 계정이 docker 그룹이어야 합니다. 파이썬·paramiko·엠파워 서버 접속은 필요 없습니다.
  • 왜 컨테이너인가 — 엠파워 서버(Rocky 8)의 PHP 는 glibc 2.28 이 필요한데 CentOS 7 은 2.17 이라 바로 돌지 않습니다. 컨테이너는 네트워크 없이(--network none) 지금 계정 권한으로 뜨고, 원본 폴더(읽기)와 결과 폴더만 붙습니다.
  • 속도 — 문서 한 건에 약 0.5초(컨테이너를 띄우는 시간 포함). 2026-10-16 에 11건이 모두 풀려 원본 지문과 같았습니다.

  • pip 이 아니라 python3 -m pip — 중계 래퍼는 셸의 python3 를 먼저 씁니다. 이렇게 설치해야 바로 그 파이썬에 들어갑니다 (pip 이 다른 파이썬을 가리키면 설치했는데도 로그에 rc=200 · relay: paramiko 가 없습니다 가 남습니다).
  • 터미널에서 !pip 로 치지 않습니다 — ! 는 Jupyter 셀 문법입니다. bash 에서 !pip 는 "pip 으로 시작한 마지막 명령을 다시 실행"이라 예전 명령(예: pip install vllm)이 불려 나옵니다. 실제로 pip install vllm install paramiko 가 돌아 vllm 빌드 오류가 났던 일이 있습니다(2026-10-16) — 이때는 아무것도 설치되지 않으니 위 명령으로 다시 하면 됩니다.
  • .cmd 를 주면 안 됩니다 — relay_removeenc.cmd 는 윈도우용이라 리눅스에서는 @echo: command not found 로 실패합니다(로그에 reason=removeenc_exit rc=2).
  • --decrypt-timeout 120 — 한 건마다 망을 오가므로 기본 60초보다 넉넉히 줍니다.
  • 접속 정보는 sample/enc_test/.env_v11(SSH_SERVER · SSH_USER_ID · SSH_USER_PWD)에서 읽습니다. 이 서버에서 엠파워 서버의 SSH(22번)로 나갈 수 있어야 합니다 — 막혀 있으면 로그에 rc=200 · relay: 서버에 연결하지 못했습니다 가 남습니다.
  • 목록의 path 는 파일 이름만 적은 상대 경로입니다(목록 파일이 있는 폴더 기준). 그래서 sample/enc 폴더째 옮기면 그대로 돕니다.

중계는 테스트 서버 · 더미 문서 전용입니다(열쇠와 풀린 문서가 망을 건넙니다). 운영에서는 엠파워 서버에서 --decrypt-cmd 없이 돌립니다. 자세한 절차와 막혔을 때는 테스트 문서 6-11(중계) · 6-12(Docker 판)를 보세요.

운영에서 주기를 권하는 이유

  • 원문이 디스크에 남지 않게 — 파일을 지워도 디스크에는 내용이 한동안 남아 복구될 수 있습니다. 잠가서 보관하던 문서의 평문이 /tmp 에 쓰였다 지워지는 것은, 잠깐이라도 암호화의 뜻을 줄입니다.
  • /tmp 가 작은 서버 — 큰 문서를 풀다가 공간이 모자라면 empty_output · size_mismatch 로 실패합니다.
  • /tmp 는 여러 계정이 함께 쓰는 곳 — 프로그램이 폴더 권한을 700 으로 잠그지만, 전용 폴더를 따로 주는 편이 관리하기 쉽습니다.
/dev/shm 은 메모리를 씁니다. 한 번에 한 건만 풀려 있으므로 필요한 양은 "가장 큰 문서 하나"만큼이지만, 압축 문서는 펼친 내부 문서까지 더해집니다. 수백 MB 짜리 문서가 섞여 있으면 여유 메모리를 먼저 확인하세요. 실행 계정에 그 폴더의 쓰기 권한이 없으면 복호화 환경 문제로 멈춥니다. ※ /dev/shm 에서의 실행은 설계·코드 기준의 설명이며, 서버에서 직접 돌려 확인하지는 않았습니다.

서버가 떠 있으면 "running":true, 바로 쓸 수 있으면 "ready":true 입니다. 출력은 언제나 한 줄입니다(위 예시는 보기 좋게 두 줄로 나눴습니다). 칸 하나하나의 뜻은 아래 출력(JSON) 읽는 법에 명령별로 정리했습니다.

내릴 서버가 없었으면 "message":"정지할 데몬 없음" · "stopped":false 입니다. 이때도 code 는 0 입니다(원하던 상태가 이미 참이므로). 칸별 뜻 ③

터미널 1의 서버가 끝나고 프롬프트가 돌아옵니다. 터미널 1에서 Ctrl+C 를 눌러도 됩니다. kill -9 로 죽여도 됩니다 — 남은 기록 파일은 다음 호출이 "죽은 기록"으로 걸러 냅니다.

출력(JSON) 읽는 법 — --serve · --status · --stop 명령별 정리

세 명령은 결과를 화면(stdout)에 JSON 한 줄로 냅니다. 옵션을 따로 줄 필요가 없습니다. 모양은 셋 다 같습니다.

{"error":{ … 명령이 잘 끝났는가 … },"daemon":{ … 서버가 지금 어떤 상태인가 … }}
묶음칸값뜻
error
세 명령 공통		 code숫자0 = 명령이 정상으로 끝남. 0 이 아니면 실패이고 그 번호가 오류 코드입니다(11장)
kind글자정상이면 "success", 실패면 오류 이름(예: "model_load_failed")
message글자사람이 읽는 한 줄 설명. 프로그램에서는 이 문구로 분기하지 마세요 — 문구는 바뀔 수 있습니다
daemon서버 상태 값. 들어 있는 칸이 명령마다 다릅니다 — 아래 ①②③. 실패(code≠0)일 때는 이 묶음이 없습니다

① --serve — 서버 띄우기

모델을 다 올려 준비가 끝난 순간 한 줄을 냅니다(그 전에는 아무것도 안 나옵니다). 그 뒤 서버가 도는 동안과 끝날 때는 더 내지 않습니다.

# 준비 완료 — 이 줄이 나오면 --daemon 호출을 받을 수 있다
{"error":{"code":0,"kind":"success","message":"model=e5-small-ko pid=248641 port=41757 준비 완료"},
 "daemon":{"running":true,"model":"e5-small-ko","pid":248641,"port":41757,"version":"0.1.0","idle_timeout":0,"ready":true}}

# 같은 모델의 서버가 이미 떠 있을 때 — 새로 띄우지 않고 바로 끝난다(종료코드 0). pid·port 는 '이미 떠 있는 서버'의 것
{"error":{"code":0,"kind":"success","message":"model=e5-small-ko: 이미 실행 중인 데몬이 있습니다"},
 "daemon":{"running":true,"model":"e5-small-ko","pid":248641,"port":41757,"version":"0.1.0","idle_timeout":0,"ready":true}}

# 실패 — 모델 파일이 없을 때(종료코드 2). daemon 묶음이 없다
{"error":{"code":3002,"kind":"model_load_failed","message":"[MpowerClassify-rs] 상주 서버가 임베딩 모델을 올리지 못했습니다 — …"}}
daemon 의 칸값뜻
runningtrue서버가 떠 있습니다(방금 띄웠거나, 이미 떠 있었거나)
readytrue / falsetrue = 모델을 다 올려 바로 답할 수 있음. "이미 실행 중"인데 그 서버가 아직 모델을 올리는 중이면 false 이고, 이때는 pid·port 가 빠질 수 있습니다
model글자서버가 물고 있는 임베딩 모델(--model 로 준 것. 기본 e5-small-ko)

port숫자서버가 듣는 포트. 뜰 때마다 빈 번호를 자동으로 잡고 이 서버 안에서만 접속됩니다(127.0.0.1 — 방화벽을 열 필요가 없습니다). 호출하는 쪽이 이 값을 알 필요는 없습니다 — --daemon 이 알아서 찾습니다
version글자서버 실행파일의 버전. 호출하는 실행파일과 다르면 다음 --daemon 호출이 서버를 새로 띄웁니다
idle_timeout숫자(초)이만큼 요청이 없으면 서버가 스스로 꺼집니다. 0 = 무한(꺼지지 않음, 기본)
상황error.code종료코드어떻게 하나
준비 완료0— (계속 실행 중)이제 --daemon 으로 부르면 됩니다
이미 실행 중00할 일 없음 — 떠 있는 서버를 그대로 씁니다

② --status — 서버 상태 묻기

언제 불러도 한 줄을 내고 바로 끝납니다(종료코드 0). 묻기만 할 뿐 서버를 띄우거나 내리지 않습니다.

# 서버가 떠 있고 준비됨
{"error":{"code":0,"kind":"success","message":"model=e5-small-ko pid=248641 port=41757 version=0.1.0 idle_timeout=무한(자동종료 없음) ready=true"},
 "daemon":{"running":true,"model":"e5-small-ko","pid":248641,"port":41757,"version":"0.1.0","idle_timeout":0,"ready":true}}

# 서버가 없음 — 이것도 code 는 0 이다. running 이 false
{"error":{"code":0,"kind":"success","message":"model=e5-small-ko: 실행 중인 데몬 없음"},
 "daemon":{"running":false,"model":"e5-small-ko"}}
daemon 의 칸값뜻
runningtrue / false서버가 떠 있는가. false 면 아래 칸 중 model 만 옵니다
readytrue / false바로 쓸 수 있는가. 서버를 띄운 직후 모델을 올리는 1~2초 동안은 running:true · ready:false 입니다
model글자물어본 모델. --status --model ko-sroberta 처럼 모델을 주면 그 모델 서버의 상태를 답합니다
pid · port · version · idle_timeout①의 표와 같습니다
이렇게 나오면뜻어떻게 하나
running:true · ready:true서버 정상그대로 --daemon 으로 호출
running:true · ready:false모델을 올리는 중1~2초 뒤 다시 확인. 기다리지 않고 --daemon 으로 불러도 됩니다 — 호출이 알아서 기다립니다
running:false서버 없음--serve 로 띄우거나, 그냥 --daemon 으로 부르면 자동으로 뜹니다

③ --stop — 서버 내리기

정지 요청을 보내고 한 줄을 낸 뒤 바로 끝납니다(종료코드 0).

# 떠 있던 서버에 정지를 보냄
{"error":{"code":0,"kind":"success","message":"데몬 정지 요청 전송"},"daemon":{"model":"e5-small-ko","stopped":true}}

# 내릴 서버가 없었음 — 원하던 상태(서버 없음)가 이미 참이라 이것도 code 0
{"error":{"code":0,"kind":"success","message":"정지할 데몬 없음"},"daemon":{"model":"e5-small-ko","stopped":false}}
daemon 의 칸값뜻
stoppedtrue / falsetrue = 떠 있던 서버에 정지 요청을 보냈음. false = 내릴 서버가 없었음
model글자정지 대상 모델. 여러 모델의 서버를 띄웠다면 --stop --model 이름 으로 하나씩 내립니다

stopped:true 는 "요청을 보냈다"는 뜻이고, 서버는 그 직후(보통 0.1초 안)에 내려갑니다. 완전히 내려갔는지까지 확인하려면 --status 로 running:false 를 보세요. 그래서 이 출력에는 running 칸이 없습니다.

4 빠른 시작

설치 폴더(/opt/MpowerClassify-rs-linux)에서 아래처럼 실행합니다. 다른 곳에서 부를 때는 실행 파일을 절대경로로 적습니다.

① 문서 한 건 — 등급을 바로 본다

./MpowerClassify-rs --file "/data/docs/계약서.hwp"

인자는 --file 하나면 됩니다. 화면에 JSON 이 나오고, 맨 끝(stderr)에 요약 한 줄이 붙습니다.

[summary] 총 1개 / 검출 1, C=1 S=0 O=0 미분류=0 추출실패=0, 총시간=26.5ms

화면의 JSON 은 원소 셋짜리 배열입니다 — 실행 헤더 · 문서 레코드 · 요약. 칸의 뜻은 결과 읽기.

② 폴더 전체 — 결과를 파일로

./MpowerClassify-rs --dir "/data/collected" --format jsonl --out "/data/out/result.jsonl"
인자뜻
--dir "/data/collected"이 폴더와 하위 폴더 전부가 대상. 압축파일은 안의 문서까지 펼쳐서 분류합니다
--format jsonl한 줄에 문서 하나로 씁니다(줄 단위로 읽기 쉬움). json 이면 배열 하나. --out 이 .jsonl 로 끝나면 생략해도 됩니다
--out "/data/out/result.jsonl"결과를 이 파일에 씁니다. 절대경로를 권합니다(폴더가 없으면 만들어 줍니다)

③ 다른 프로그램에서 부를 때 — 표준형

./MpowerClassify-rs --dir "/data/collected" --json-errors --simple --nosummary \
    --format jsonl --out "/data/out/result.jsonl"
인자무엇을 하나빼면
--json-errors끝날 때 상태 한 줄({"error":{code,…}})을 stdout 마지막에 냅니다. 성공해도 나옵니다(code:0) 실패를 문장으로 받게 됩니다 — 문구가 바뀌면 연동이 깨집니다
--simple문서 레코드를 다섯 칸(file · hash · doc_id · grade · doctype)으로 줄입니다 레코드에 판정 근거까지 수십 칸이 실립니다
--nosummary맨 끝의 집계 레코드({"summary":…})를 뺍니다문서 줄 사이에 집계 줄이 섞입니다(건수는 상태 줄의 total 로 옵니다)

5 실행 방법 — 무엇을 할 때 어떤 인자

아무 모드 인자가 없으면 분류가 기본입니다. 아래 표의 인자를 주면 그 일만 하고 끝납니다.

하려는 일인자설명
분류 (기본)--file · --dir · --files-from · --filelist 보안등급과 업무분류를 한 번에 매깁니다. 대상 인자 넷 중 하나를 줍니다
규칙만으로 빠르게--rule-only임베딩 모델을 읽지 않습니다. 규칙이 못 정한 문서는 null 로 남습니다
기준 문서 비교로만--vector-only --seeds …규칙을 쓰지 않고 seed 와 닮은 정도로만 등급을 정합니다
한 축만--axis security · --axis doctype보안등급만 / 업무분류만. doctype 은 개인정보 검출을 건너뛰어 더 빠릅니다
전파만 다시--propagate 1차결과.jsonl문서도 모델도 읽지 않고, 벡터가 든 1차 결과에 seed 비교만 다시 합니다
본문만 뽑아 보기--text-only분류하지 않고 추출한 본문만 냅니다(파서 확인용)
규칙 파일 검사--check-rules문서를 읽지 않고 규칙 파일이 올바른지만 봅니다(정상 0 · 틀리면 4)

임베딩 상주 서버--serve · --status · --stop · --daemon모델을 물고 있는 서버를 띄워 한 건씩 부를 때의 시간을 줄입니다(★ 서버 장)

등급은 어떻게 정해지나

아래 신호들이 각자 등급을 내고, 그중 가장 민감한 등급이 최종 등급이 됩니다. 어느 신호도 등급을 못 내면 null(검토 대상)입니다.

신호무엇을 보나예
rule 내용본문의 개인정보 패턴(주민번호 · 계좌 · 주소 등 20종)과 키워드 사전. 여러 개인정보가 함께 있으면 올려 줍니다(결합)주민번호 + 계좌 → C
sensitive 민감정보법에서 정한 민감정보 낱말(건강 · 범죄경력 · 노조 · 정치 등)"진단서" · "형사처벌" → C
stamp 표식문서에 찍힌 보안 표식. 문서 머리(앞 400자)에 있거나 2번 이상 나올 때만 인정합니다"대외비" → C · "내부용" → S

⑤ 상태 줄 — {"error":{…}}

이름이 error 지만 성공했을 때도 나옵니다(code 가 0). 부르는 쪽은 stdout 의 마지막 줄만 읽으면 됩니다. --out 으로 저장한 파일의 맨 끝에도 같은 줄이 들어갑니다.

{"error":{"code":3001,"kind":"extract_failed","message":"2건 중 1건을 읽지 못했습니다",
          "path":"/data/collected","total":2,"failed":1,
          "rule_version":"cso-2026.09.2","taxonomy_version":"doctype-gen-6a2aa502557a",
          "doctype_rule_version":"doctype-gen-6a2aa502557a"}}
칸값뜻
code숫자0 = 성공. 0 이 아니면 그 번호가 오류 코드입니다. 이 값으로 분기합니다 — 한번 정한 번호는 뜻이 바뀌지 않습니다
kind글자code 와 짝이 맞는 이름(success · extract_failed · no_input …). 로그에서 눈으로 읽을 때 씁니다
message글자사람이 읽는 설명. 성공이면 "". 이 문구로 분기하지 마세요 — 문구는 다듬어질 수 있습니다
path글자이번 실행의 대상, 또는 문제가 된 파일. 경로와 상관없는 오류에는 이 칸이 없습니다
total숫자다룬 문서 수. 문서를 읽기 전에 멈춘 실패에는 없습니다
failed숫자그중 못 읽은(또는 풀지 못한) 문서 수. 결과 파일은 그래도 만들어지고, 그 문서의 레코드에 error 칸이 붙습니다
rule_version글자이번에 쓴 보안등급 규칙(cso_rule.yaml)의 판
doctype_rule_version · taxonomy_version글자이번에 쓴 업무분류 규칙(doc_rule.yaml)과 그 안의 분류체계의 판

판(version) 세 칸은 결과와 함께 보관하세요. 나중에 규칙이 바뀌었을 때 "어느 기준으로 내린 판정인지"를 가리는 유일한 근거입니다. 규칙을 읽기 전에 멈춘 실패에는 이 칸들이 없습니다.

등급 스트림 기록 — Windows 전용 2026-10-19 추가

분류한 문서의 NTFS 대체 데이터 스트림 :mgrade 에 최종 등급(C/S/O)을 쓰는 옵션입니다. PC 보안 에이전트가 문서를 열 때 이 값을 읽어 등급별로 허용·차단합니다. 형식은 NEOGradeToolApp -s 와 같은 12바이트("MGRD" · 버전 1 · 등급)입니다. 설계: 등급스트림-기록-옵션-설계

인자값설명
--write-grade-stream—켜기. 등급이 정해진 문서에 최종 등급을 씁니다. 이미 같은 값이면 쓰지 않습니다. 압축 안 문서는 건너뛰고 압축 파일 자체에 집계 등급, 못 읽은 문서는 건너뜁니다
--grade-stream-unclassifiedskip | none등급을 못 정한 문서: skip=건드리지 않음(기본), none=NONE(0) 기록
--grade-stream-update-time—쓸 때 수정 시각이 바뀌게 둡니다. 주지 않으면(기본) 생성·접근·수정 시각을 그대로 둡니다
리눅스에서는 쓸 수 없습니다 — 대체 데이터 스트림은 Windows(NTFS)에만 있어, 리눅스에서 --write-grade-stream 을 주면 문서를 읽기 전에 1012 unsupported_option(종료코드 3)으로 멈춥니다. ntfs-3g 로 마운트한 NTFS 볼륨이어도 마찬가지입니다(에이전트가 읽는 경로가 아님). 리눅스 서버에서 분류한 결과로 마킹하려면 Windows 에서 같은 옵션으로 다시 돌리세요. 보조 옵션(--grade-stream-unclassified · --grade-stream-update-time)만 주면 1003. 자세한 동작(결과의 grade_stream · 오류 4002)은 Windows 실행가이드의 '등급 스트림 기록' 절.

사람이 정한 등급 2026-10-20 추가

--grade-overrides <cso_override.jsonl> 로 담당자 결정이 판정을 이기게 하고, --set-grade C|S|O|NONE --file <문서>(또는 --filelist <목록>)로 문서에 바로 등급을 정합니다(결정 목록에 덧붙이려면 --reviewer · --reason). 리눅스에서도 결과 레코드와 결정 목록은 그대로 동작하고, 파일 표식(--write-grade-stream)만 Windows 전용입니다. 없는 목록 2009(종료 3) · 목록 쓰기 실패 2010(종료 4). 자세한 것은 Windows 실행가이드의 '사람이 정한 등급' 절.

9 배치 스크립트 예시

매일 밤 수집 폴더를 분류해 날짜별 결과를 남기고, 상태 줄의 code 로 갈라 처리하는 스크립트입니다. 그대로 가져다 경로만 고쳐 쓰면 됩니다.

#!/usr/bin/env bash
# classify_nightly.sh — 수집 폴더를 분류하고 결과를 날짜별로 남긴다
set -u

APP=/opt/MpowerClassify-rs-linux/MpowerClassify-rs
SRC=/data/collected
OUTDIR=/data/classify/out
OUT="$OUTDIR/result_$(date +%Y%m%d).jsonl"

export CSOCLASSIFY_LOGDIR=/var/log/mpowerclassify     # 로그를 한곳에(없으면 실행파일 옆 log/)
mkdir -p "$OUTDIR" "$CSOCLASSIFY_LOGDIR"

# 상태 줄은 stdout 의 '마지막 줄' — 성공이든 실패든 언제나 있다
STATUS=$("$APP" --dir "$SRC" --json-errors --simple --nosummary \
               --format jsonl --out "$OUT" | tail -n 1)

# jq 가 있으면 jq 로, 없으면 grep 으로 code 를 꺼낸다
if command -v jq >/dev/null; then
    CODE=$(printf '%s' "$STATUS" | jq -r '.error.code')
    FAILED=$(printf '%s' "$STATUS" | jq -r '.error.failed // 0')
else
    CODE=$(printf '%s' "$STATUS" | grep -o '"code":[0-9]*' | head -n 1 | cut -d: -f2)
    FAILED=$(printf '%s' "$STATUS" | grep -o '"failed":[0-9]*' | cut -d: -f2)
fi

case "${CODE:-}" in
    0)    echo "완료: $OUT" ;;
    3001|3004)
          echo "완료(못 읽은 문서 ${FAILED:-?}건): $OUT"      # 결과는 정상 — 그 문서만 사람·OCR 로
          grep '"error"' "$OUT" | grep -v '^{"error"' > "$OUTDIR/failed_$(date +%Y%m%d).jsonl" ;;
    3002|3003)
          echo "경고: 임베딩 모델을 못 올렸습니다 — 규칙 등급만 나갔습니다: $OUT" >&2 ;;
    1???) echo "명령이 틀렸습니다: $STATUS" >&2; exit 3 ;;
    2???) echo "정책 파일을 확인하세요: $STATUS" >&2; exit 4 ;;
    4???) echo "결과를 쓰지 못했습니다: $STATUS" >&2; exit 1 ;;
    "")   echo "상태 줄이 없습니다 — 프로세스가 죽었을 수 있습니다(로그 확인)" >&2; exit 1 ;;
    *)    echo "실패: $STATUS" >&2; exit 1 ;;
esac
읽는 법
· 종료코드를 직접 보려면 파이프를 쓰지 말고 "$APP" … > status.txt; RC=$? 로 받거나, bash 라면 ${PIPESTATUS[0]} 를 쓰세요. code 와 종료코드는 늘 짝이 맞으므로 둘 중 하나로만 갈라도 됩니다.
· 모르는 code 는 천의 자리로 뭉뚱그리면 됩니다 — 1000번대 부른 쪽 잘못 · 2000번대 정책 파일 · 3000번대 처리 · 4000번대 출력. 나중에 새 오류가 늘어도 옳은 갈래에 들어갑니다.
· 상태 줄이 아예 없으면 프로세스가 비정상 종료한 것입니다 — "줄이 없음"을 성공으로 읽지 마세요.

14 주의사항

  • Windows 에서 만든 결과와 섞어 쓸 때 — 같은 모델 파일이라도 ONNX Runtime 이 OS·CPU 마다 미세하게 다른 수를 냅니다 (실측: 같은 OS 안에서는 두 판이 코사인 1.000000, Linux↔Windows 는 최저 0.996). 임계값 바로 옆의 문서는 OS 에 따라 전파 판정이 갈릴 수 있으니, 1차 분류와 전파, seed 등록은 같은 OS 에서 하세요.
  • 임베딩 모델을 바꾸면 seed 도 다시 만드세요. --model 은 e5-small-ko(기본)·e5-small·ko-sroberta 를 받고, 배포본에는 e5-small-ko 만 들어 있습니다. 다른 모델은 models/<별칭>/ 에 model.onnx·tokenizer.json 을 넣습니다. 차원이 다르면 1013 으로 멈추지만, 차원이 같은 두 모델을 섞으면 오류 없이 유사도만 틀어집니다.
  • 같은 seed 파일을 여러 프로세스가 동시에 고치지 마세요. --seed-add --seeds 는 파일을 잠그고 통째로 다시 씁니다. 웹·여러 작업자가 부른다면 --seeds 없이 불러 등록될 줄만 stdout 으로 받고, 한 곳에서 모아 쓰는 편이 안전합니다.
  • --textsave · --with-pii 는 개인정보를 평문으로 남깁니다. 남길 폴더의 권한(chmod 700)과 보관 기간을 먼저 정하세요. 기본 실행은 검출된 원문 값을 결과에도 로그에도 남기지 않습니다.
  • 스캔 PDF(그림만 든 PDF)는 처리제외입니다 — OCR 을 하지 않습니다. 레코드에 "excluded":"scan_pdf" 가 붙고 실패로 세지 않습니다.
  • NFS·CIFS 위의 문서도 그대로 읽습니다. 다만 마운트가 끊긴 폴더는 "대상 없음"(1001)으로 보이니, 배치 앞에서 마운트를 확인하세요.
  • 도움말은 ./MpowerClassify-rs --help — ①~⑪ 로 나뉘어 있고, 이 판에서 되는 것과 안 되는 것이 ⑩·⑪ 에 적혀 있습니다.
