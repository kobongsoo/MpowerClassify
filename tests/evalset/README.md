# 평가셋 — 만들기와 채점

규칙을 고친 뒤 **"좋아졌나 나빠졌나"를 숫자로 답하기 위한 도구** 두 개가 여기 있다.

| 파일 | 하는 일 |
|---|---|
| `build_evalsets.py` | 문서를 층화 표집해 사람이 정답을 적을 라벨링 시트(xlsx)를 만든다 |
| `score_evalsets.py` | 정답이 채워진 평가셋으로 엔진을 채점한다 |

평가셋 xlsx 는 고객사 실데이터라 저장소에 없다(`/resources/golden_dataset/` 는 gitignore).
`resources/golden_dataset/` 에 모아 둔다(2026-10-22 `report/` 에서 옮김).

| 파일 | 무엇 | 쓰는 곳 |
|---|---|---|
| `업무분류-평가셋-500-20260918-사람재검-01.xlsx` | 업무분류 **기준 정답지** — 사람이 다시 본 판 | `bm25_experiment.py` · `bm25_fields_experiment.py` 기본값, `score_evalsets.py --doctype-xlsx` 로 지정 |
| `업무분류-평가셋-500-20260914.xlsx` | 업무분류 원본(사람 132 + AI 라벨 368) | `score_evalsets.py` 기본값 |
| `보안등급-C재현율-평가셋-500-20260914.xlsx` | 보안등급(C 재현율 중심) | `score_evalsets.py` 기본값 |
| `업무분류-정밀도검증셋-라벨링시트.xlsx` | 업무분류 1단계 정밀도 검증셋(150건) | 참고 |
| `기준문서-보안등급-라벨링시트-20260921.xlsx` | 기준 문서 중 보안등급이 없던 41건 | 기준 문서 보강 |

> `build_evalsets.py` 는 옛 검증셋을 `resources/golden_dataset/` 에서 읽고, 새로 만든 라벨링 시트는
> 정답이 비어 있으므로 골든데이터셋을 덮지 않게 `report/` 에 쓴다. 정답을 다 채운 뒤 골든데이터셋으로 옮긴다.

## 빠른 채점 — 평가셋을 만든 시점의 성적

```bash
python tests/evalset/score_evalsets.py
```

xlsx 의 `ref_` 열(평가셋을 만들 때 찍어 둔 판정)로 채점한다. 빠르지만
**규칙을 고쳐도 값이 변하지 않는다** — 그 시점의 기록일 뿐이다.

## 규칙을 고친 뒤 — 정상 흐름

### 1) 엔진을 다시 돌린다

채점할 규칙 폴더를 `CSOCLASSIFY_POLICY_DIR` 로 가리키고, `build_evalsets.py` 와
같은 명령으로 돌린다.

```bash
CSOCLASSIFY_POLICY_DIR=/d/Project/MpowerClassify/ui/policy \
  ./Rust/target/release/MpowerClassify-rs.exe \
  --filelist work/filelist.jsonl --rule-only --format jsonl --out work/run_new.jsonl
```

`work/filelist.jsonl` 은 `{"path": "...", "sfile_id": "..."}` 한 줄씩이다.
`build_evalsets.py` 를 한 번 돌리면 작업 폴더에 같은 모양으로 남는다.

> exe 는 **제자리에서** 돌린다. `target/release` 밖으로 복사하면 옆에 있는
> `pdfium.dll` 을 못 찾아 PDF 추출이 통째로 실패한다.

### 2) 채점한다

```bash
python tests/evalset/score_evalsets.py --run work/run_new.jsonl
```

### 3) 고치기 전과 견준다

```bash
python tests/evalset/score_evalsets.py --run work/run_new.jsonl --prev work/run_old.jsonl
```

어느 문서의 판정이 어떻게 바뀌었는지(`놓침→적중`, `적중→오라벨` …)까지 찍는다.
**규칙을 고친 뒤에는 이 명령의 출력을 근거로 채택/반려를 결정한다.**

## 옵션

| 옵션 | 뜻 |
|---|---|
| `--axis doctype\|security\|both` | 채점할 축(기본 both) |
| `--run JSONL` | 채점할 엔진 실행 결과 |
| `--prev JSONL` | 견줄 이전 실행 결과 |
| `--details` | 놓침·오부착 목록을 분류별로 펼친다 — **규칙에 넣을 말을 찾는 자리** |
| `--json 경로` | 결과를 json 으로도 남긴다 |
| `--src-dir` | `ref_상대경로` 를 붙일 문서 뿌리(기본 `D:\분류함`) |
| `--doctype-xlsx` / `--security-xlsx` | 평가셋 경로 바꾸기(기본 `resources/golden_dataset/` 의 20260914 판). 기준 정답지로 채점하려면 `--doctype-xlsx resources/golden_dataset/업무분류-평가셋-500-20260918-사람재검-01.xlsx` |

종료코드는 정상 `0`, **정답 시트에 앞뒤가 안 맞는 줄이 있으면 `2`** 다
(숫자는 그래도 찍는다).

## 읽는 법

### 업무분류

```
적중     정답으로 단 분류를 엔진도 달았다
오라벨   엔진이 달긴 달았는데 정답이 아니다
놓침     정답이 있는데 엔진이 아무것도 안 달았다
헛라벨   정답이 '없음'인데 엔진이 달았다
정상무라벨 정답이 '없음'이고 엔진도 안 달았다

정밀도 = 적중 / (적중+오라벨+헛라벨)
재현율 = 적중 / (적중+오라벨+놓침)
```

오라벨은 양쪽 분모에 다 들어간다 — 틀린 라벨을 붙인 동시에 정답을 놓친 것이라 그렇다.

### 보안등급

C 를 놓치지 않는 것이 이 평가셋의 목적이라 C 기준으로 가른다
(`C적중`·`C놓침`·`C오탐`·`비C정상`). 등급을 실제보다 높게 매긴 비율은
C 정밀도에 안 잡히므로 `과대등급` 으로 따로 센다.

### 표본 vs 모집단

층화 표집이라 표본 비율이 곧 전체 비율이 아니다. 층마다
`모집단 수 / 표본 수` 로 가중한 추정치를 함께 낸다.
**보고할 때는 둘 다 말한다** — 표본만 말하면 과장되고, 모집단만 말하면
표본이 몇 건이었는지 숨는다.

### 정답 출처별 (`사람` / `AI` / `검토권장`)

업무분류 평가셋은 정답 500건 중 상당수를 AI 가 달았다. **AI 가 단 정답은
엔진과 같은 단서를 봤을 수 있어 성적이 실제보다 좋게 나온다.**
수치를 인용할 때는 `사람` 부분집합의 성적을 함께 말한다.

> 알아 둘 왜곡: 2026-09-14 에 DC_007(엠파워제품)을 나중에 넣으면서, 원래 사람이
> 정답을 달았던 행에도 `[AI라벨·DC_007]` 표식이 붙었다. 그 행들은 정답1 은
> 사람 것인데 `AI` 로 세어져, `사람` 표본이 132건에서 105건으로 줄어 보인다.
